# LAST POST — 메시지 중심 진행

현재 구현은 플레이 가능한 개발 버전이다. 실제 SNS·메일 발송이나 외부 검색을 하지 않는다.

## 플레이 흐름

첫 방문에는 검정 화면의 여섯 장면 프롤로그로 시작한다. 6월 18일 마지막 게시물, 19일 연락 두절과 신고, 20일 언니의 부탁, 친구인 플레이어의 역할, 의문, MOMENT 접속 순서다. 장면은 6.5초마다 진행하며 마지막 화면은 직접 조사 시작 버튼을 누를 때까지 기다린다. 이전/다음/일시 정지/건너뛰기를 지원한다. 기존 저장은 유지되며 OS 메뉴에서 프롤로그를 다시 볼 수 있다.

1. 공개 생일 사진의 촬영일을 확인해 로그인한다. 업로드 날짜와 촬영 날짜는 다르다.
2. 이가은에게 마지막 상황을 묻고, 답장에 첨부된 게시물과 박현우 대화로 이동한다.
3. 과거 여행 기록과 사라진 스토리를 비교한다. 김태준의 설명으로 USB와 계약 분쟁을 확인한다.
4. 서라에게 관련 자료를 요청하고 공개 기록, 서울 행사 사진, 예약 게시물의 모순을 조사한다.
5. 삭제된 기록과 대화를 연결해 만남을 재구성한다. 원본 이미지와 휴대전화 사용 기록을 확인한다.
6. 사진에서 계정 연결을 확인하거나, 확보한 기록을 제시해 정민석의 DM 진술을 받는다.
7. 구조 기사와 계약 메일을 확인하고, 핵심 증거 세 개를 Notes에 저장해 가족에게 제출한다.

## 구현 원칙

- ‘다음 조사 안내’는 현재 확보한 사실에서만 다음 행동을 제안한다. 접어서 숨길 수 있다.
- 질문은 조사 조건을 만족하면 열린다. 답장이 도착한 뒤 첨부 자료를 열 수 있다.
- 과거 윤아의 대화와 현재 플레이어의 대화는 분리한다.
- 12개 추가 대화 그룹은 자료 요청, 증언 보완, 기록 대조, 후속 행동 안내를 담당한다.
- 위협적인 질문은 위험도를 높인다. 이미 저장한 증거는 유지한다.
- 신뢰를 잃은 대화에는 관계 회복 경로가 있다. 일부 삭제 자료는 증언으로 보완한다.
- 선택, 답장 대기, 증거, 노트 편집은 자동 저장한다.

## 개발자용 스포일러

로그인 암호는 `1103`. 핵심 제출 증거는 이미지 원본 출처, 서울 현장 기록, 계정 연결 사진 또는 작성 사실을 인정한 DM이다. 계약·USB·만남·이미지 가져오기 기록도 확인해야 한다. 구조 기록 확인 여부는 생존 엔딩에 영향을 준다.

순수 진행 규칙은 `engine.ts`, 추가 대화는 `dialogueExtras.ts`, 다음 행동 안내는 `leads.ts`에서 관리한다. 기존 LAST SEEN 저장과는 별도 키 `lastPostSave.v1`을 쓴다.
